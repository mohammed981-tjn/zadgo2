# الذراع الخادمية — تكامل فيربيز↔Supabase (نمط الخانق التدريجي)

> قرار المالك 2026-08-16: لا استبدال لفيربيز دفعة واحدة — عقل خادمي
> يُبنى فوقه عضواً عضواً. Firestore يبقى مصدر الحقيقة التشغيلي، ودوال
> Supabase Edge هي «الطرف الموثوق» الذي يفعل ما حُرِّم على أجهزة
> العملاء. الخارطة الكاملة في `dev-docs/roadmap-ar.md`.

## الذراع ١ — `price-audit` (فاحص الأسعار)

يفحص طلبات اليوم: العمولة المختومة، وأسعار الأصناف مقابل المنيو، ووجود
الصنف في المنيو أصلاً — ويكتب تقريره في `server_reports/price_audit`
حيث تعرضه شاشة «التشخيص» في لوحة الإدارة. **كشفٌ لا منع**.

## خطوات التفعيل (مرة واحدة)

1. **مفتاح خدمة جديد** (بيد المالك): كونسول Google Cloud ← IAM ←
   Service Accounts ← إنشاء حساب باسم `supabase-arm` ← امنحه دور
   **Cloud Datastore User** فقط (لا Firebase Admin — أقل صلاحية تكفي)
   ← Keys ← Add key ← JSON. **مفتاح مستقل عن مفتاح النشر عمداً**: إن
   انكشف أحدهما بُتر وحده.
2. **الأسرار** (بيد المالك): لوحة Supabase (المشروع الثاني) ← Edge
   Functions ← Secrets:
   - `FIREBASE_SERVICE_ACCOUNT` = نص ملف JSON كاملاً.
   - `ARM_TRIGGER_KEY` = قيمة عشوائية طويلة (تمنع تشغيل الفحص من غريب).
3. **النشر** (بيد مساعد التطبيق عبر اتصال Supabase):
   `deploy price-audit` من هذا المجلد.
4. **الجدولة**: يدوياً الآن (نداء بترويسة `x-arm-key`)، وتُضاف جدولة
   يومية (cron) في دفعة لاحقة.

## قاعدة الحماية المرافقة

`server_reports/*`: قراءة للمدير حصراً، وكتابة العملاء ممنوعة كلياً —
يكتبها حساب الخدمة وحده (يتجاوز القواعد بطبيعته).

## الذراع ٢ — `driver-balance` (رصيد الكابتن خادمياً)

تجمع حركات `driver_transactions` لكل كابتن (كلٌّ بمبلغه المُوقَّع) وتكتب
المجموع في `drivers/{id}/balance` بمفتاح الخدمة (قناعٌ على `balance`
وحده). الهدف (بند ٥): جعل الرصيد المجمَّع **مشتقّاً خادمياً** بدل أن
يكتبه جهاز الكابتن مباشرةً. تقريرها في `server_reports/driver_balance`.

**الحدّ المقصود**: `driver_transactions` محروسةٌ نوعاً (لا مكافأة يسكّها
السائق، ولا تعديل ولا حذف) لكن `amount` يكتبه الجهاز في حركات التوصيل —
فهذه الذراع تُزيل أضعف سطح (كتابة الرصيد المجمَّع)، وتحصينُ `amount`
مقابل الطلب المصدر دفعةٌ تالية.

### خطوات التفعيل (الترتيب حرجٌ كي لا يتعطّل رصيد الكابتن)

1. **النشر** (مساعد التطبيق عبر موصّل Supabase، أو المالك بالـCLI:
   `supabase functions deploy driver-balance`). الأسرار نفسها الذراع ١.
2. **تشغيل وتحقّق**: نادِها (`?key=…`) وقارن الأرصدة المكتوبة بما تحسبه
   الأجهزة — يجب أن تتطابق (فترة تعايش، بلا تغيير سلوكي).
3. **تحويل التطبيق**: أوقف كتابة `balance` المباشرة من الجهاز في المواضع
   الستة (يبقى تسجيل الحركة فقط، والذراع تُجمّع).
4. **إغلاق القاعدة**: أضِف `balance` إلى قائمة المنع في قواعد `drivers`
   — بعد أن صار الخادم مصدر الرصيد وحده.

**الجدولة**: يدوياً الآن (`?key=`)، وcron يومي/عند فتح اللوحة لاحقاً.

## القادم في هذا المجلد

- الذراع ٢ (تتمّة): تحصين `amount` مقابل orders + إشعار الكابتن (FCM).
- الذراع ٣: التعويض الآلي المسقوف + حدّ معدل طلبات الانضمام.
- النسخ اليومي: تصدير المجموعات المهمة إلى Postgres (نسخة ثانية آمنة
  «مرآة تقرأ ولا تُكتب» — لا ازدواج مصدر حقيقة).
