| الدالة | النوع | تحلّ |
|---|---|---|

## قبل النشر — ثلاثة أشياء بالترتيب

### ١) تنبيه الميزانية

`Google Cloud Console` ← `Billing` ← `Budgets & alerts` ← `Create Budget`
— ٥٠ ريالاً، تنبيهات على ٥٠٪ و٩٠٪ و١٠٠٪.

**وهو ليس مكبحاً — هو جرس.** المكبح مضبوط في الكود:
`maxInstances: 10` على كل دالة، وحارس خروج مبكر داخل `onOrderWrite`
يخرج فوراً إن لم يتغيّر حقلٌ يستحق إشعاراً. بهذين يصير أسوأ سيناريو
محدوداً رياضياً مهما ساء الكود.

### ٢) تأكيد المنطقة

في `index.js` ثابتٌ واحد:

```js
const REGION = 'us-central1';
```

يجب أن يطابق **منطقة Firestore**، وإلا عبَر كل نداء قارّةً فبطؤ وكلّف.
تجدها: كونسول Firebase ← Firestore Database ← أيقونة ⓘ بجانب
`(default)`؛ أو في Google Cloud Console ← Firestore ← عمود `Location`
في قائمة القواعد. المقابلات الشائعة: `nam5` → `us-central1`، `eur3` →
`europe-west1`، `me-central1` → `me-central1`.

### ٣) المفتاح السري لميسر

```bash
firebase functions:secrets:set MOYASAR_SECRET_KEY
```

يُلصق المفتاح (`sk_live_…`) عند السؤال. يُخزَّن في Secret Manager ولا
يظهر في الكود ولا في المستودع ولا في السجلّات. بدونه تردّ `/verify.php`
بـ`503 moyasar_not_configured` ولا تتعطّل بقية الدوال.

## النشر

```bash
npm install -g firebase-tools     # مرة واحدة
firebase login
cd <جذر المستودع>
firebase deploy --only functions
```

الأمر يطبع عنوان دالة `api`. خذه وأضف إليه `/notify.php` واضبطه متغيّر
مستودع في GitHub:

```
Settings ← Secrets and variables ← Actions ← Variables
ZADGO_NOTIFY_URL = https://<عنوان api>/notify.php
```

**لماذا `notify.php` واللاحقة لا معنى لها هنا؟** لأن التطبيق يشتقّ عنوان
التحقق من الدفع باستبدال `notify.php` بـ`verify.php` في هذا المتغيّر
نفسه. فبقبول الدالة للمسارين يخدم متغيّرٌ واحد النقطتين، **بلا تغيير
سطر في كود التطبيق**. ومسار `/notify.php` نفسه يردّ رداً فارغاً ناجحاً
لأن الإشعارات صار يتولّاها مُطلَق Firestore لا نداءُ التطبيق.

ثم أعد بناء الحزم الأربع كي تحمل العنوان.

## الاختبار بعد النشر

1. سجّل دخولاً في تطبيق المطعم وتطبيق الكابتن على جهازين، واقبل إذن
   الإشعارات.
2. **أغلق تطبيق المطعم تماماً** (اسحبه من قائمة التطبيقات الأخيرة).
3. أنشئ طلباً من تطبيق العميل.
4. يجب أن يصل إشعار «🛎️ طلب جديد» بصوت والتطبيق مغلق.

### إن لم يصل

```bash
firebase functions:log --only onOrderWrite
```

| ما تراه في السجلّ | المعنى |
|---|---|
| `إشعار طلب جديد { sent: 0 }` | الدالة عملت ولا توكن لأحد — لم يسجّل مديرو المطعم دخولاً بعد التحديث. اطلب منهم الخروج والدخول |
| لا شيء إطلاقاً | المُطلَق لم يُنشر أو المنطقة خاطئة |
| `فشل إرسال إشعار` مع رمز | الرمز يقول السبب؛ توكن ميت يُمحى تلقائياً ولا يتكرر |

## ما يبقى في التطبيق ولا يُحذف بعد

`lib/providers/notify_relay.dart` صار زائداً، لكنه **معطَّل أصلاً** ما
لم يُضبط `ZADGO_NOTIFY_URL`، ونداؤه بعد الضبط يردّ ردّاً فارغاً ناجحاً.
يُحذف بعد أسبوع من تشغيل الدوال بلا عطل — لا قبله، فبقاؤه لا يضرّ
وحذفه المبكر يُلغي شبكة الأمان الوحيدة.

## المرحلة الثانية (بعد استقرار الأولى بيوم)

| الدالة | تحلّ |
|---|---|
| `onOrderAssignable` | **الإصلاح البنيوي**: الإسناد التلقائي يعمل اليوم داخل تطبيق المطعم وحده — فإن أُغلق لم يُسنَد الطلب لأحد. نقلُه هنا يُنهي هذا الصنف من الأعطال كلّه |
| `reconcileDrivers` | مجدولة كل ١٥ دقيقة، تُصفّر عدّاد حمولة كابتن لا طلب جارياً له — تُغني عن الترقيع الحالي داخل التطبيق |
