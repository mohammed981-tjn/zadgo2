# نبضة Supabase — منع إيقاف مشروع zol-adcraft المجاني

آخر تحديث: 2026-08-15

## المشكلة

مشاريع Supabase المجانية **تتوقف بعد ٧ أيام بلا نشاط** (لا شهرين كما
شاع) — والإيقاف لا يمحو البيانات لكنه يُسقط التطبيق حتى تُستعاد يدوياً.
أي طلب API واحد يصفّر عدّاد الخمول، فنبضة كل يومين تكفي وزيادة.

## الحل الجاهز في هذا المستودع

`.github/workflows/supabase-keepalive.yml` — يعمل كل يومين (05:41 UTC)
ويرسل طلبَين خفيفين للمشروع. **خطوتان لتفعيله:**

1. **سرّان في المستودع**: Settings → Secrets and variables → Actions →
   New repository secret:
   - `SUPABASE_URL`: من لوحة Supabase → Settings → API → Project URL
   - `SUPABASE_ANON_KEY`: من نفس الصفحة → anon public key
2. **وصول الملف إلى main**: جدولة GitHub لا تعمل إلا من الفرع الافتراضي،
   وmain مجمّد بأمر المالك (2026-08-14) — فدفع هذا الملف وحده إليه
   يحتاج أمراً صريحاً منه.

## بدائل بلا GitHub

- **موافقة أداة Supabase**: حين يظهر طلب سماح لأداة Supabase أو أداة
  «الروتين المجدول» في واجهة الجلسة واعتمدها المالك، يُنشأ روتين يفتح
  جلسة كل يومين تنفّذ `select now();` على المشاريع النشطة — بلا أسرار
  ولا main إطلاقاً.
- **cron-job.org** (يدوي، ٥ دقائق): حساب مجاني → New cronjob → الرابط
  `https://<project-ref>.supabase.co/rest/v1/?apikey=<anon-key>` →
  كل يوم. يغني عن كل ما سبق لمن لا يريد GitHub.

## لماذا ليست النبضة داخل قاعدة البيانات نفسها؟

`pg_cron` يعمل داخل القاعدة، والخمول يُقاس بالطلبات **الواردة من الخارج**
— نشاط داخلي لا يصفّر العدّاد، فالنبضة يجب أن تأتي من خادم خارجي.
