# تصفير التجربة — خطة الانتقال إلى التشغيل الحقيقي

> سؤال المالك 2026-08-12: «نحن الآن في فترة التجربة، إذا أردنا تصفير
> التطبيق وقواعد البيانات ماذا نفعل؟»
>
> **آخر تحديث: 2026-08-12.**

---

## ⚠️ اقرأ هذا قبل أي حذف

**١) لا يوجد تراجع.** حذفُ مستند في Firestore نهائي، ولا نسخة احتياطية
عندك اليوم (النسخ المجدولة تحتاج Blaze — بند مؤجَّل). فقبل أول حذف:
صدّر ما يهمّك من لوحة الإدارة (تقارير Excel/PDF) واحتفظ به.

**٢) الأخطر ليس الحذف — بل الحذف الناقص.** أرصدة الكباتن ومحافظ العملاء
**حقولٌ مخزَّنة** في مستنداتهم، لا مجاميع تُحسب من الحركات. فحذفُ
`driver_transactions` وحده يترك كابتناً برصيد ٣٤٠ ر.س **بلا حركة واحدة
تفسّره** — دفترٌ يكذب، وهو أسوأ من دفترٍ ممتلئ ببيانات تجربة.
فالقاعدة: **احذف الحركات وصفّر الحقول معاً، لا إحداهما**.

**٣) الحذف من الكونسول على حاسوب لا جوال** — واجهة الجوال تجعل الضغطة
الخاطئة أسهل.

---

## ١) ما يُحذف — بيانات التجربة

من [كونسول فايربيز](https://console.firebase.google.com/) ← Firestore ←
اضغط النقاط الثلاث بجانب اسم المجموعة ← **Delete collection**:

| المجموعة | ما فيها |
|---|---|
| `orders` | كل الطلبات |
| `order_proofs` | صور وأزمنة الاستلام والتسليم |
| `chat_messages` | محادثات العميل والكابتن |
| `complaints` + `complaint_messages` | الشكاوى وردودها |
| `driver_transactions` | دفتر حساب الكباتن |
| `wallet_transactions` | حركات محافظ العملاء |
| `restaurant_settlements` | دفعات المطاعم |
| `payout_requests` | طلبات سحب الكباتن |
| `reassignments` | سجلّ إعادة الإسناد |
| `coupon_usages` | استخدامات الكوبونات |
| `verified_payments` | أختام دفعات التجربة |
| `admin_audit` | سجلّ عمليات الإدارة (اختياري — قد تُبقيه للتاريخ) |

---

## ٢) ما **لا** يُحذف

| المجموعة | لماذا تبقى |
|---|---|
| `restaurants` + `items` + `categories` | **منيوهاتك المستوردة** — فطير ستيشن ٧٤ صنفاً وكبسة سويلم ٢٦. حذفها يعني إعادة الاستيراد كلّه |
| `users` | حسابات الدخول. حذف المستند **لا يحذف حساب Firebase Auth** — فيبقى الشخص قادراً على الدخول بلا ملف، وهي حالة تُربك التطبيق |
| `drivers` | ملفات الكباتن — تُصفَّر حقولها لا تُحذف (الخطوة ٣) |
| `delivery_settings` | التسعير والحوافز وسقف الحمولة — أعدادُك المضبوطة |
| `coupons` · `banners` · `broadcasts` | تُراجَع وتُعدَّل، لا تُحذف بالجملة |
| `registrationCodes` · `invite_codes` | أكواد تسجيل الكباتن السارية |
| `driver_applications` + `driver_application_docs` | طلبات انضمام حقيقية إن وُجدت |

---

## ٣) تصفير الحقول المخزَّنة — **لا تتخطَّ هذه الخطوة**

بعد حذف الحركات، صفّر ما تركته وراءها. في الكونسول، افتح كل مستند
وعدّل الحقل:

### في كل مستند داخل `drivers`

| الحقل | القيمة | لماذا |
|---|---|---|
| `balance` | `0` | الرصيد بإشارة (سالب = نقدٌ بيده) |
| `totalEarnings` | `0` | إجمالي الأرباح |
| `pendingPayout` | `0` | الحقل القديم |
| `activeOrders` | `0` | عدّاد الحمولة |
| `isAvailable` | `true` | وإلا بقي «مشغولاً» بطلبات لم تعد موجودة |
| `clusterLat` / `clusterLng` | احذف الحقلين | مرساة عنقود لطلبٍ محذوف |
| `rating` / `ratingCount` | `0` | تقييمات تجربة |
| `warningCount` | `0` | إنذارات تجربة |
| `offersTotal` / `offersAccepted` | `0` | معدل القبول |
| `referralRewarded` | `false` | وإلا لم يُصرف حافز الإحالة الحقيقي |
| `lastChallengeWindow` | احذف الحقل | تحدي أسبوع منقضٍ |

### في كل مستند داخل `users` (العملاء)

| الحقل | القيمة |
|---|---|
| `walletBalance` | `0` |

### في كل مستند داخل `restaurants`

| الحقل | القيمة |
|---|---|
| `rating` / `ratingCount` | `0` |

> **مؤشّر تحقّق:** بعد الانتهاء افتح **الإدارة ← التشخيص ← افحص الآن**.
> يجب أن يخرج التقرير: صفر طلبات جارية، وكل كابتن `عدّاده 0 | الفعلي 0`،
> وبلا أي ⚠️. **إن بقيت علامة تحذير فالتصفير ناقص** — وهذه أسرع طريقة
> للتأكد بدل مراجعة المستندات واحداً واحداً.

---

## ٤) على الأجهزة نفسها

بيانات محلية لا تُمسّ بحذف القاعدة:

- **سلة العميل** محفوظة على جهازه (`SharedPreferences`).
- **الجولة التعريفية** «شوهدت» فلا تظهر مجدداً.
- **توكن الإشعارات** يُعاد تسجيله عند أول دخول.

**الحل لجهاز واحد:** إعدادات الهاتف ← التطبيق ← التخزين ← **مسح
البيانات**. أو ببساطة: أعد تثبيت التطبيق.

---

## ٥) ماذا عن حسابات الدخول؟

حساباتك وحسابات الكباتن الحقيقيين **تبقى**. أما حسابات التجربة الوهمية
فتُحذف من **موضعين معاً** وإلا بقي نصفها:

1. كونسول فايربيز ← **Authentication** ← احذف المستخدم.
2. Firestore ← `users` (و`drivers` إن كان كابتناً) ← احذف مستنده.

> حذف واحدٍ دون الآخر يُنتج حالتين مربكتين: حسابُ دخولٍ بلا ملف (يدخل
> ويرى شاشة مكسورة)، أو ملفٌ بلا حساب (يظهر في قوائمك ولا يستطيع الدخول).

---

## ٦) الترتيب الموصى به — لا تخلطه

1. **صدّر التقارير** التي تريد الاحتفاظ بها (Excel/PDF من لوحة الإدارة).
2. **ألغِ** كل الطلبات الجارية من المتابعة الحيّة أولاً — أنظف من حذفها
   وهي «جارية»، ويحرّر عدّادات الكباتن تلقائياً.
3. **احذف** مجموعات القسم ١.
4. **صفّر** حقول القسم ٣.
5. **امسح بيانات** التطبيقات على أجهزتك.
6. **افحص** بشاشة التشخيص — حتى يخرج التقرير نظيفاً بلا ⚠️.

---

## ٧) ولماذا لا أبني زرّ «تصفير» في لوحة الإدارة؟

لأنه **سلاحٌ محشوّ يبقى في التطبيق إلى الأبد**. زرٌّ يُفرّغ قاعدة
البيانات، مهما أُحيط بتأكيدات، ينتظر ضغطةً خاطئة يوم يكون في القاعدة
طلبات حقيقية وأرصدة حقيقية. والتصفير عمليةٌ تقع **مرة واحدة** في عمر
المشروع — فلا يستحق أن يُقايَض بخطرٍ دائم.

وإن أردتَه رغم ذلك، أبنيه بشرطين: لا يعمل إلا وقاعدة البيانات دون
٥٠ طلباً، ويطلب كتابة اسم المشروع حرفياً قبل التنفيذ. قل «ابنِ زرّ
التصفير» وأنفّذه بهما.
