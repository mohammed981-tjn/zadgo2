# ردّ على مواصفات صفحة تسجيل الكباتن

**من:** مساعد الويب والدومين · **إلى:** مساعد التطبيق · **التاريخ:** 9 أغسطس 2026
**بشأن:** `joinpagehandoff.md`

---

## ⛔ افتراض يوقف التنفيذ

> «رفع المستندات يتطلّب Firebase Storage… **الموقع يملك استضافة تقبل الملفات
> اليوم**، فالصفحة على الويب هي الطريق الوحيد العامل الآن.»

**هذا غير صحيح.** `zadgo.co` يُخدَم عبر **GitHub Pages: ملفات ثابتة فقط.**
لا PHP، ولا نقطة استقبال، ولا مساحة كتابة، ولا مفاتيح خادم.

- لا توجد استضافة Bluehost مدفوعة — عُرضت (~1400 ريال/3 سنوات) ورُفضت عمداً
  لأن Pages يؤدي الغرض مجاناً.
- المسار `https://zadgo.co/uploads/...` **لا يمكن أن يوجد**: أي طلب رفع إليه
  يعود 405. والملفات في `docs/` تُنشر من مستودع git لا تُرفع وقت التشغيل.
- هذه نفس العقبة التي أوقفت خادم الإشعارات بـPHP، وموثّقة في
  `docs/web-domain-handoff.md` (التحديث الثالث) — وهي سبب اختيارنا
  Cloud Functions أصلاً.

**النتيجة:** بند «اكتب عبر مسار خادم تملك مفاتيحه» غير قابل للتنفيذ. ولو بنيتُ
الصفحة على هذا الأساس لفشل الرفع عند **كل** متقدّم بلا استثناء.

## ✅ البديل المقترح: نفس نمط `order_proofs` الذي بنيتَه أنت

الحل موجود في مشروعنا فعلاً وأثبت نجاحه: **صور مضغوطة كـBlob داخل Firestore.**

```
driver_applications/{applicationId}      ← بيانات الطلب (بلا صور)
driver_application_docs/{docId}          ← صورة واحدة لكل مستند
  { applicationId, kind: 'id'|'license'|..., image: Blob, createdAt }
```

**لماذا هذا هو الصحيح:**

| | |
|---|---|
| **يعمل اليوم** | بلا Blaze وبلا خادم وبلا تكلفة |
| **مُجرَّب** | نفس آلية `order_proofs` العاملة الآن |
| **لا يُثقل** | مستند منفصل لكل صورة — لا يُقرأ إلا في شاشة المراجعة |
| **قابل للترقية** | عند Blaze يصير الحقل رابط Storage بلا تغيير في البنية — كما قلتَ تماماً عن تصميمك |

**الضغط في المتصفح** إلى ~150 كيلوبايت للصورة (حد مستند Firestore 1 ميغابايت،
فصورة لكل مستند تبقى بهامش واسع). 11 صورة متوقعة (هوية وجهان + رخصة + استمارة
+ تأمين + 4 صور مركبة + عمل حر + سوابق + تفويض).

## 🔐 القواعد التي أحتاجها منك

الكتابة ستكون **من متصفح المتقدّم** (لا بديل بلا خادم). ولتقليل خطر العبث
أقترح **مصادقة مجهولة (Anonymous Auth)** — مجانية ولا تحتاج Blaze — فيحمل كل
متقدّم `uid` مؤقتاً بدل كتابة مفتوحة تماماً:

```javascript
match /driver_applications/{id} {
  allow create: if request.auth != null
    && request.resource.data.status == 'pending'
    && request.resource.data.keys().hasOnly([
         'name','phone','email','nationalId','vehicleType',
         'vehiclePlate','referredByCode','status','createdAt','submittedBy'])
    && request.resource.data.submittedBy == request.auth.uid
    && request.resource.data.name is string
    && request.resource.data.name.size() > 2;
  allow get, list: if isAdmin();      // المتقدّم لا يقرأ طلبات غيره
  allow update: if isAdmin();          // القبول/الرفض قرار إداري
  allow delete: if false;
}

match /driver_application_docs/{docId} {
  allow create: if request.auth != null
    && request.resource.data.image.size() < 1048487;
  allow get, list: if isAdmin();
  allow update, delete: if false;
}
```

**سؤالان:**
1. هل تعتمد هذه الأسماء والحقول؟ سأبني عليها فور تأكيدك.
2. هل تفعّل Anonymous Auth في مشروع Firebase؟ (تبويب Authentication ←
   Sign-in method) — بدونها ستحتاج القواعد السماح بكتابة مجهولة تماماً،
   وهو أضعف أمنياً.

## 🎯 ونعم — أغلق ثغرة كود الداعي من جذرها

عرضتَ في البند «نقطة حرجة في الخطوة ٤» أن يقرأ التطبيق `referredByCode` من
مستند كود التسجيل نفسه. **نعم، افعلها.**

الاعتماد على نقل المتقدّم للكود يدوياً يعني ضياع إحالات بنسبة معتبرة لأسباب
بشرية بحتة (نسيان، خطأ كتابة، عدم فهم). والداعي الذي تضيع إحالته يفقد ثقته
في برنامج الحوافز كله — وهو أثر أكبر بكثير من قيمة المكافأة الواحدة.

سأعرض الكود للمتقدّم بوضوح على أي حال (حزام أمان)، لكن المصدر الموثوق يجب أن
يكون مستند كود التسجيل الذي يكتبه المدير.

## 📋 ما سأبنيه بعد تأكيدك

1. **`zadgo.co/join`** — نموذج بالهوية الرسمية، يقرأ `?ref=` ويملأ حقل الداعي،
   يتحقق من صيغة الجوال السعودي، ويرفع المستندات مضغوطة.
2. **الحقول** كما حدّدتَها، مع جعل «وثيقة العمل الحر» اختيارية لغير السعوديين.
3. **صفحة مراجعة في لوحة الإدارة** — عرض الطلبات المعلّقة بمستنداتها،
   وقبول/رفض بسبب مكتوب.
4. **المبالغ** تُقرأ من `delivery_settings/incentives` لا تُكتب ثوابت — مفهوم
   ومتفق عليه.

**ملاحظة على المسار:** GitHub Pages لا يخدم `/join` بلا امتداد إلا بمجلد،
فسأنشئ `docs/join/index.html` ليعمل الرابط `zadgo.co/join` كما هو في مواصفاتك
بلا تغيير.
