# فحص قواعد Firestore بمحاكٍ حقيقي

القواعد خطُّ دفاعنا الوحيد (لا Cloud Functions — البند د١)، وقراءتها بالعين
لا تكفي: قاعدةٌ تبدو صحيحة قد تسمح بما لا تتوقّع. هذه الاختبارات تشغّل
**محاكي Firestore الرسمي** بقواعد المستودع نفسها، وتحاول الكتابة والقراءة
بهويات مختلفة، وتتحقق أن كل محاولة قُبلت أو رُفضت كما ينبغي.

## التشغيل

```bash
cd tools/rules-test
npm i                     # مرة واحدة: @firebase/rules-unit-testing + firebase
cp ../../firestore.rules .
npx firebase-tools emulators:exec --only firestore --project demo-zadgo \
    "node suggestions.test.mjs"
```

يحتاج **Java** (يشغّل المحاكي) وإنترنتاً في أول مرة (ينزّل ملف المحاكي).

## ما يغطّيه `suggestions.test.mjs` — ٢٥ حالة

صندوق «قل لنا»: إنشاءٌ سليم · نصٌّ أقصر من الحدّ · نصٌّ أطول منه · اسمٌ
ووسيلة تواصل فوق الحدّ · **حقلٌ نصّيّ ليس نصّاً** · انتحال `uid` غيره ·
حالةٌ غير `new` · غياب النصّ · قراءة الزائر لاقتراحه وسرده للمجموعة ·
غير المسجَّل كتابةً وقراءة · تعديل الزائر وحذفه · المدير قراءةً وسرداً
وتغييرَ حالةٍ وحذفاً · **منع المدير من تحريف نصّ الزائر** · الدعم يقرأ
ولا يعدّل ولا يحذف.

## إن أضفت مجموعةً جديدة

أضف ملف اختبارٍ بجانب هذا. الكلفة دقائق، والبديل أن تُكتشف الثغرة بعد
النشر — وقواعدنا تُنشر آلياً على الإنتاج فور وصول `main`.
