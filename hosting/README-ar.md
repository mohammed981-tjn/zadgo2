# دليل تهيئة الدومين zadgo.co على Bluehost — خطوة بخطوة

> هذا الدليل موجّه لمالك ZadGo. اتبع الخطوات بالترتيب، وكل خطوة مستقلة يمكن
> التوقف بعدها والمتابعة لاحقاً.

## ملخص الوضع الحالي (بتاريخ 2026-08-07)

| البند | الحالة |
|---|---|
| تسجيل الدومين | ✅ مسجّل، وخوادم الأسماء على Bluehost (ns1/ns2.bluehost.com) |
| ربط الدومين باستضافة | ❌ يعرض حالياً صفحة «ركن» (Parking) — غير مربوط بأي استضافة فعلية |
| شهادة SSL (https) | ❌ لا تعمل — تُفعَّل بعد ربط الاستضافة |
| GitHub Pages | ⚠️ محاولة قديمة غير مكتملة (ملفا CNAME في المستودع) — لن نستخدمها |

**الخلاصة:** الدومين جاهز من ناحية التسجيل، لكن لا توجد استضافة نشطة مربوطة به.
يجب أولاً التأكد هل اشتريتَ خطة استضافة من Bluehost أم الدومين فقط.

---

## الخطوة 1: التأكد من وجود استضافة

1. ادخل إلى <https://www.bluehost.com> واضغط **Login**.
2. من اللوحة الرئيسية ابحث عن قسم **Hosting** أو **My Sites**.
3. **إذا رأيت خطة استضافة نشطة** → انتقل للخطوة 2.
4. **إذا لم توجد استضافة** (يظهر الدومين فقط) → اشترِ خطة **Starter**
   (تكفي تماماً لصور المنيو ولوحة التحكم والموقع التعريفي — حوالي 3.99$/شهر
   بالعقد الطويل). أثناء الشراء اختر أن الدومين لديك مسبقاً: **zadgo.co**.

## الخطوة 2: ربط الدومين بالاستضافة

1. من لوحة Bluehost اذهب إلى **Domains**.
2. تأكد أن `zadgo.co` معيَّن كدومين رئيسي (Primary Domain) للاستضافة،
   أو أضفه عبر **Assign / Add Domain** إن لم يكن معيَّناً.
3. بما أن خوادم الأسماء أصلاً على Bluehost، لا حاجة لأي تغيير DNS يدوي —
   الربط يتم تلقائياً خلال دقائق إلى ساعات قليلة.
4. للاختبار: افتح `http://zadgo.co` — يجب أن تختفي صفحة الإعلانات/الركن
   وتظهر صفحة Bluehost فارغة أو صفحة موقعك.

## الخطوة 3: تفعيل شهادة SSL المجانية (https)

1. من لوحة Bluehost: **Security** ← **SSL Certificate** (أو داخل cPanel:
   **SSL/TLS Status**).
2. فعّل **Free SSL (Let's Encrypt / AutoSSL)** للدومين `zadgo.co`
   و `www.zadgo.co`.
3. انتظر حتى ساعة، ثم افتح `https://zadgo.co` — يجب أن يظهر القفل 🔒
   بدون تحذيرات. **روابط الصور في التطبيق كلها تبدأ بـ https، فهذه الخطوة
   إلزامية.**

## الخطوة 4: رفع صور المنيو

1. من لوحة Bluehost افتح **cPanel** ثم **File Manager**.
2. ادخل مجلد **public_html**.
3. أنشئ داخله مجلداً جديداً باسم: `images` (بأحرف إنجليزية صغيرة).
4. ادخل مجلد `images` واضغط **Upload** ثم ارفع:
   - ملف `.htaccess` الموجود في هذا المستودع تحت
     `hosting/public_html/images/.htaccess`
     (إن لم يظهر الملف بعد الرفع: فعّل **Show Hidden Files** من إعدادات
     File Manager).
   - صور المنيو **بنفس الأسماء التالية حرفياً** (لأن التطبيق يطلبها بهذه
     الأسماء):

   | اسم الملف المطلوب | الصنف |
   |---|---|
   | `fateer-halloum.jpg` | فطير جبن حلوم |
   | `fateer-honey.jpg` | فطير بالعسل |
   | `fateer-cheddar-honey.jpg` | فطير جبن شيدر وعسل |
   | `fateer-halawa-cream.jpg` | فطير حلاوة وجبنة سائلة |
   | `fateer-egg-cream.jpg` | فطير بيض بالبنه |

5. **الاختبار:** افتح في المتصفح
   `https://zadgo.co/images/fateer-honey.jpg`
   يجب أن تظهر الصورة نفسها مباشرة (وليس صفحة أو تنزيلاً). إذا ظهرت،
   فروابط التطبيق ستعمل تلقائياً.

### نصائح للصور
- الصيغة: JPG، والأبعاد حوالي 800×600 تكفي.
- حجم كل صورة يُفضَّل أقل من 300 كيلوبايت (اضغطها عبر أي أداة ضغط صور)
  حتى يفتح المنيو بسرعة عند العملاء.
- الأسماء بأحرف إنجليزية صغيرة وشرطات فقط — بدون مسافات أو أحرف عربية.

## الخطوة 5 (لاحقاً): تنظيف بقايا GitHub Pages

في المستودع ملفا `CNAME` (في الجذر وفي `docs/`) من محاولة قديمة لربط
الدومين بـ GitHub Pages لم تكتمل. بعد نجاح الخطوات أعلاه يُنصح بحذفهما
وإيقاف GitHub Pages من إعدادات المستودع (Settings ← Pages) إن كان مفعّلاً،
لتجنّب أي تعارض مستقبلي. **لا تحذف شيئاً قبل أن يعمل الموقع على Bluehost.**

## ما يأتي بعد ذلك (خارج هذا الدليل)

- **لوحة تحكم ويب مقيّدة الدخول:** ستُبنى على الدومين وتقرأ من Firestore
  عبر Firebase Web SDK مع تسجيل دخول — تُحدَّد متطلباتها في محادثة مخصّصة.
- **صفحة تعريفية للشركة** ونسخة الويب من التطبيق.

## محاذير ثابتة

- بيانات التطبيق تبقى في **Firestore** — لا تُنشأ قاعدة MySQL على Bluehost.
- لا تُنشر كلمات مرور أو مفاتيح حسّاسة في المستودع.
